BUILD COMMANDS
===============
Whole-branch build (Turborepo, orchestrates all 3 npm workspaces):
  npm install
  npx turbo run build
  npx turbo run test

SaaS Platform uses Turborepo as its build orchestrator - a real,
widely-used enterprise choice (Vercel), common among SaaS companies
running multi-package/multi-app repos. Root package.json declares npm
workspaces (backend, frontend-react, frontend-angular) and turbo.json
defines the build/test pipeline.

PROVEN CACHE HIT (Turborepo's actual reason for existing here - not
just running 3 scripts): with no source changes between runs,
  Run 1: Tasks: 2 successful, 2 total | Cached: 0 cached, 2 total | Time: 7.574s
  Run 2: Tasks: 2 successful, 2 total | Cached: 2 cached, 2 total | Time: 39ms >>> FULL TURBO
Run 2 replayed both frontend builds from content-hash cache instead of
re-executing vite/ng - genuinely faster, not decorative.

Per-module (still available individually):
backend:
  cd backend && npm install && npm test && npm start   # listens on $PORT or 3000

frontend-react (customer app):
  cd frontend-react && npm install && npm test && npm run build

frontend-angular (admin app):
  cd frontend-angular && npm install && npx ng build && npx ng test --watch=false --browsers=ChromeHeadless

ARCHITECTURE
============
Multi-Product SaaS Platform: ONE backend, TWO API namespaces.

  backend/src/routes/customer.js  GET /api/customer/products (public namespace)
  backend/src/routes/admin.js     GET /api/admin/products (internal, +internalCost/margin)
  backend/src/routes/plans.js     GET /api/plans, GET /api/plans/:id (shared, non-namespaced)
  backend/src/data/               products.js, plans.js data layers
  GET /health

  frontend-react/     Customer App (React)
    - fetches ONLY /api/customer/products
    - never calls /api/admin/*

  frontend-angular/   Admin App (Angular)
    - fetches ONLY /api/admin/products
    - never calls /api/customer/*

The two frontends are connected to the SAME backend but are kept on
separate API namespaces by convention - a real multi-product SaaS
platform boundary, not disconnected apps sharing nothing. Contrast
with the Micro-Frontend Platform (React embeds Angular live via
iframe) and the Migration Bridge (one backend route-splits between
stacks) - here the split is by API namespace, not by route or by
embedding.

  backend/quality/          13 real JS code-quality tool fixtures
  frontend-angular/quality/ 21 real TypeScript code-quality tool fixtures
  (no duplication: JS tools live once in backend/, TS tools live once
  in frontend-angular/; frontend-react connects via real API calls)
